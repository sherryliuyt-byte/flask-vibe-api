# API 交換格式

本文整理前端與 Flask API 的 JSON 交換格式。範例中的 ID 從 `1` 起算，實際 ID 以 API 回應為準；金額皆為測試資料，不代表程式內的固定金額。

> **來源註記：**指定講義 `專案-個人記帳本/01-從資料表到-API.md` 不在目前工作區，故固定錯誤句及完整 `error_code` 對照無法核對。本文先依目前程式與本次任務明確提供的 `conflict.unique_name` 整理，未核實項目列於最後的「與現況的差異」。

## 共通規則

所有 API 回應外層皆為以下三個鍵：

```json
{
  "code": 200,
  "message": "查詢成功。",
  "data": {}
}
```

| HTTP 狀態 | 意義 |
|---|---|
| `200` | 查詢、更新或處理成功；清單沒有資料時仍回 `200`，`data` 為 `[]`。 |
| `201` | 新增成功。 |
| `400` | 請求格式、欄位值或資料規則不符合。 |
| `404` | 路徑中的資料不存在。 |
| `500` | 資料庫操作失敗。 |
| `405` | 不支援的 HTTP 方法。 |

- 客戶端不送 `id`、`created_at` 或 `updated_at`；這些欄位由伺服器或資料庫管理。若請求附帶這些欄位，API 不以客戶端值作為主鍵或建立時間。
- 日期使用 `YYYY-MM-DD` 字串；月合計的月份使用 `YYYY-MM`。
- 金額、數量、價格、比例及匯率在回應中以十進位字串表示，避免浮點數精度損失。輸入可使用 JSON 數字或十進位字串。
- 時間戳記使用含時區的 ISO 8601 字串，例如 `2026-08-01T00:00:00+00:00`。
- 可空欄位在回應中保留欄位並以 `null` 表示，不以省略欄位代替。
- `PATCH` 只更新允許的欄位；主鍵與伺服器產生時間不由客戶端更新。

## 帳戶 `accounts`

端點：`GET /api/accounts`、`POST /api/accounts`、`GET /api/accounts/{account_id}`、`PATCH /api/accounts/{account_id}`。

成功範例（現金錢包）：

```json
{
  "code": 201,
  "message": "帳戶新增成功。",
  "data": {
    "id": 1,
    "name": "現金錢包",
    "kind": "cash",
    "currency": "TWD",
    "opening_balance": "0",
    "statement_day": null,
    "payment_day": null,
    "created_at": "2026-08-01T00:00:00+00:00",
    "updated_at": "2026-08-01T00:00:00+00:00"
  }
}
```

| 欄位 | 型別 | 請求／回應 | 說明 |
|---|---|---|---|
| `id` | integer | 僅回應 | 資料庫產生的 ID。 |
| `name` | string | 新增必填；PATCH 可改 | 帳戶名稱，必須唯一。 |
| `kind` | string | 新增必填 | `cash`、`bank`、`credit_card`、`broker`。 |
| `currency` | string | 新增可省略；回應必填 | 三碼大寫幣別；省略時為 `TWD`。 |
| `opening_balance` | decimal string | 新增可省略；回應必填 | 未提供時由資料庫預設為 `0`。 |
| `statement_day` | integer or null | 可空 | 結帳日，PATCH 可改。 |
| `payment_day` | integer or null | 可空 | 繳款日，PATCH 可改。 |
| `created_at`、`updated_at` | timestamp | 僅回應 | 建立與更新時間。 |

### 帳戶餘額

端點：`GET /api/accounts/{account_id}/balance`。

```json
{
  "code": 200,
  "message": "帳戶餘額取得成功。",
  "data": {
    "account_id": 1,
    "currency": "TWD",
    "balance": "500",
    "balance_twd": "500"
  }
}
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `account_id` | integer | 帳戶 ID。 |
| `currency` | string | 帳戶幣別。 |
| `balance` | decimal string | 原幣別餘額。 |
| `balance_twd` | decimal string | 台幣等值餘額。 |

成功範例（轉帳 200）：

```json
{
  "code": 201,
  "message": "移轉新增成功。",
  "data": {
    "id": 1,

    "amount": "200",

    "note": null,
    "created_at": "2026-08-02T00:00:00+00:00",
    "updated_at": "2026-08-02T00:00:00+00:00"
  }
}
```

| 欄位 | 型別 | 請求／回應 | 說明 |
|---|---|---|---|
| `id` | integer | 僅回應 | 移轉 ID。 |
| `transferred_on` | date string | 必填 | 移轉日期。 |

| `from_account_id`、`to_account_id` | integer | 必填 | 轉出與轉入帳戶，不可相同。 |
| `note` | string or null | 可空 | 備註。 |
| `created_at`、`updated_at` | timestamp | 僅回應 | 建立與更新時間。 |

成功範例（台積電買進 10 股）：

```json
{
  "code": 201,
  "message": "投資交易新增成功。",
  "data": {
    "id": 1,
    "instrument_id": 1,
    "account_id": 2,
    "trade_type": "buy",

    "currency": "TWD",
    "fx_rate_to_twd": "1",
    "voided_at": null,
    "created_at": "2026-08-10T00:00:00+00:00",
    "updated_at": "2026-08-10T00:00:00+00:00"
  }

```

| 欄位 | 型別 | 請求／回應 | 說明 |

| `voided_at` | timestamp or null | 可空 | 作廢時間；若有值須含時區。 |
| `created_at`、`updated_at` | timestamp | 僅回應 | 建立與更新時間。 |

## 發票 `invoices`

端點：`POST /api/invoices`、`GET /api/invoices`、`GET /api/invoices/{invoice_id}`、`PATCH /api/invoices/{invoice_id}`。

成功範例（發票 `AB12345678`，詳情回應包含品項與花費 ID）：

```json
{
  "code": 200,
  "message": "發票資料取得成功。",
  "data": {
    "id": 1,
    "number": "AB12345678",
    "issued_on": "2026-08-08",
    "amount": "70",
    "kind": "paper",
    "currency": "TWD",
    "fx_rate_to_twd": "1",
    "random_code": null,
    "seller_name": null,
    "seller_ban": null,
    "prize_status": "unchecked",
    "created_at": "2026-08-08T00:00:00+00:00",
    "updated_at": "2026-08-08T00:00:00+00:00",
    "items": [
      {
        "id": 1,
        "invoice_id": 1,
        "name": "午餐",
        "quantity": "1",
        "unit_price": "70",
        "line_amount": "70",
        "created_at": "2026-08-08T00:00:00+00:00",
        "updated_at": "2026-08-08T00:00:00+00:00"
      }
    ],
    "expense_ids": [1]
  }
}
```

| 欄位 | 型別 | 請求／回應 | 說明 |
|---|---|---|---|
| `id` | integer | 僅回應 | 發票 ID。 |
| `number` | string | 新增必填；PATCH 不可改 | 兩碼大寫英文字母加八碼數字，唯一。 |
| `issued_on` | date string | 新增必填；PATCH 不可改 | 開立日期。 |
| `amount` | decimal string | 新增必填；PATCH 不可改 | 發票金額，大於零。 |
| `kind` | string | 新增必填；PATCH 不可改 | `paper` 或 `electronic`。 |
| `currency` | string | 新增可省略；回應必填 | 省略時為 `TWD`。 |
| `fx_rate_to_twd` | decimal string | 新增時可省略條件值 | 幣別為 `TWD` 且未提供時使用 `1`；其他情況必須提供且大於零。 |
| `random_code` | string or null | 可空；PATCH 可改 | 有值時為四碼數字。 |
| `seller_name`、`seller_ban` | string or null | 可空；PATCH 可改 | 賣方資料。 |
| `prize_status` | string | 回應；PATCH 僅可設 `void` | `unchecked`、`lost`、`won`、`claimed`、`void`。 |
| `created_at`、`updated_at` | timestamp | 僅回應 | 建立與更新時間。 |
| `items` | array | 詳情回應 | 發票品項清單。 |
| `expense_ids` | integer array | 詳情回應 | 關聯花費 ID 清單。 |

## 月合計 `GET /api/summary`

查詢參數 `month` 必填，格式 `YYYY-MM`。

成功範例（2026 年 8 月：午餐 70；買進台積電不併入入帳或花費）：

```json
{
  "code": 200,
  "message": "月收支摘要取得成功。",
  "data": {
    "month": "2026-08",
    "income_twd": "0",
    "expense_twd": "70"
  }
}
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `month` | string | 查詢月份，`YYYY-MM`。 |
| `income_twd` | decimal string | 該月入帳金額乘匯率後的加總；沒有資料時為 `"0"`。 |
| `expense_twd` | decimal string | 該月花費金額乘匯率後的加總；沒有資料時為 `"0"`。 |

買進、賣出等 `trades` 不會直接併入月入帳或月花費。若一筆入帳透過 `trade_id` 關聯投資交易，月合計只讀該筆 `incomes`，不 join 或重算交易現金流。

## 錯誤回應

錯誤回應仍使用 `code`、`message`、`data` 三個鍵，`data` 為 `null`。

400 範例（帳戶名稱重複）：

```json
{
  "code": 400,
  "message": "帳戶名稱已存在。",
  "data": null
}
```

404 範例（找不到帳戶）：

```json
{
  "code": 404,
  "message": "找不到這個帳戶。",
  "data": null
}
```

回應 JSON 不包含約束名、資料表名、SQLSTATE、例外類別或堆疊。

## 內部錯誤

以下為 `conflict.unique_name` 的內部日誌示意。日誌欄位只寫入伺服器日誌，不出現在回應 JSON；前端只讀取 `code`、`message`、`data`。

日誌欄位示意：

| 鍵 | 說明 |
|---|---|
| `timestamp` | 日誌時間。 |
| `level` | 日誌嚴重程度。 |
| `request_id` | 請求追蹤 ID。 |
| `method`、`path` | HTTP 方法與路徑。 |
| `status_code` | 對應 HTTP 狀態碼。 |
| `error_code` | 供伺服器端分類錯誤的代碼。 |
| `resource`、`field` | 發生衝突的資源與欄位。 |

目前可由本次任務確認的 `error_code`：

| `error_code` | 意義 | HTTP 狀態 |
|---|---|---|
| `conflict.unique_name` | 唯一名稱衝突。 | `400` |

日誌範例：

```json
{
  "timestamp": "2026-08-01T00:00:00+00:00",
  "level": "WARNING",
  "request_id": "req-example-1",
  "method": "POST",
  "path": "/api/accounts",
  "status_code": 400,
  "error_code": "conflict.unique_name",
  "resource": "accounts",
  "field": "name"
}
```
