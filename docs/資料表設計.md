# 個人記帳本資料表設計

## 共通規則

- 所有表都有 `id`、`created_at`、`updated_at`。`id` 是資料庫產生的整數主鍵，建立後不更新；`created_at` 是必填的 `timestamptz`，插入時由資料庫填入 UTC 時間；`updated_at` 是必填的 `timestamptz`，每次更新時由程式寫入 UTC 時間。
- 除發票品項外，所有外鍵刪除規則都是 `ON DELETE RESTRICT`；主鍵不允許更新。唯一例外是刪除發票時，其品項可使用 `ON DELETE CASCADE` 一起刪除。其他仍有參照的父列不能刪除。
- 金額使用可含小數的 `numeric`，股數使用可含小數的 `numeric`。幣別使用三碼大寫英文字母；匯率表示一單位該幣別可換得的台幣金額，必須大於零，幣別為 `TWD` 時必須等於 1。上述格式與匯率規則以資料庫 `CHECK` 約束表達。
- 帳戶建立後幣別固定。入帳、花費、移轉及投資交易的幣別須符合其所記錄的帳戶幣別；移轉兩端可使用不同幣別，各自記錄金額與匯率。這些跨表比對由 API 在寫入前檢查。
- 本設計不提供刪除帳務列的 API。金額、股數等數值存交易明細，不存可直接修改的目前餘額或目前持有股數。

## 1. `accounts`（帳戶）

記錄現金、銀行、信用卡及券商交割戶。帳戶獨立成表，讓各種帳務列都能參照同一個帳戶，並由帳務明細統一計算帳戶餘額。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `name` | 必填 | 帳戶名稱，不得重複。 |
| `account_type` | 必填 | 限 `cash`、`bank`、`credit_card`、`brokerage_cash`；由資料庫 `CHECK` 限制。 |
| `currency` | 必填 | 三碼大寫幣別代碼；由資料庫 `CHECK` 限制。建立後不變；API 檢查相關明細幣別相同。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**無。

## 2. `opening_balances`（帳戶期初金額）

記錄帳本開始追蹤時各帳戶已有的金額。獨立成表，讓期初金額與之後的交易分開保存，也避免把可變的目前餘額放進帳戶主檔。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `account_id` | 必填 | 每個帳戶最多一筆期初金額；唯一。 |
| `amount` | 必填 | 可為正、零或負；負數可表示信用卡期初欠款。 |
| `currency` | 必填 | 三碼幣別，須與帳戶幣別相同；格式由資料庫檢查，跨表相同由 API 檢查。 |
| `fx_rate` | 必填 | 換算台幣匯率，依共通匯率規則。 |
| `effective_at` | 必填 | 開始追蹤的時間，`timestamptz`。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`account_id` → `accounts.id`。

**完整性：**建立帳戶時由 API 在同一筆資料庫交易中建立其期初金額。`account_id` 的唯一約束確保不會有第二筆期初金額。

## 3. `income_categories`（入帳分類）

記錄入帳可選的分類。獨立成表，讓分類名稱可重用，並與花費分類分開管理。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `name` | 必填 | 入帳分類名稱，不得重複。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**無。

## 4. `expense_categories`（花費分類）

記錄花費可選的分類。獨立成表，讓分類名稱可重用，且名稱唯一性只在花費分類內計算。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `name` | 必填 | 花費分類名稱，不得重複。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**無。

## 5. `income_entries`（入帳）

記錄薪水、獎金、利息、退款、發票中獎獎金，以及投資現金股利或減資退回現金。獨立成表，以便分類、計算帳戶金額及記錄其來源。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `account_id` | 必填 | 收入帳戶。 |
| `category_id` | 必填 | 入帳分類。 |
| `amount` | 必填 | 大於零的金額；由資料庫 `CHECK` 限制。 |
| `currency` | 必填 | 三碼幣別，須與帳戶幣別相同；跨表檢查由 API 執行。 |
| `fx_rate` | 必填 | 換算台幣匯率，依共通匯率規則。 |
| `received_at` | 必填 | 入帳時間，`timestamptz`。 |
| `invoice_id` | 可空 | 發票中獎入帳來源；一張發票最多連結一筆入帳，唯一。 |
| `trade_id` | 可空 | 投資交易來源；一筆投資交易最多連結一筆入帳，唯一。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`account_id` → `accounts.id`；`category_id` → `income_categories.id`；`invoice_id` → `invoices.id`；`trade_id` → `trades.id`。兩個來源外鍵各自可空且唯一，刪除仍被參照的父列時拒絕刪除。

**完整性：**API 驗證來源目標存在，資料庫以唯一約束限制每個來源至多連結一筆入帳；目前不依投資交易種類強制入帳帳戶或金額配對，也不限制兩個來源欄位不可同時有值。

## 6. `expense_entries`（花費）

記錄消費及其實際影響帳戶的時間。獨立成表，因消費時間與信用卡入帳／扣款時間可能不同，且需記錄花費分類與付款帳戶。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `account_id` | 必填 | 記錄花費的帳戶。 |
| `category_id` | 必填 | 花費分類。 |
| `amount` | 必填 | 大於零的金額；由資料庫 `CHECK` 限制。 |
| `currency` | 必填 | 三碼幣別，須與帳戶幣別相同；跨表檢查由 API 執行。 |
| `fx_rate` | 必填 | 換算台幣匯率，依共通匯率規則。 |
| `spent_at` | 必填 | 實際消費時間，`timestamptz`。 |
| `posted_at` | 必填 | 此筆花費反映到帳戶的時間，`timestamptz`；可與 `spent_at` 不同。 |
| `note` | 可空 | 補充說明。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`account_id` → `accounts.id`；`category_id` → `expense_categories.id`。

## 7. `transfers`（帳戶移轉）

記錄帳戶間的資金移轉。獨立成表，避免把同一筆移轉錯記為入帳或花費。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `from_account_id` | 必填 | 移出帳戶。 |
| `to_account_id` | 必填 | 移入帳戶，必須與移出帳戶不同；由資料庫 `CHECK` 限制。 |
| `from_amount` | 必填 | 移出帳戶金額，大於零；由資料庫 `CHECK` 限制。 |
| `from_currency` | 必填 | 三碼幣別，須符合移出帳戶幣別；由 API 在寫入前檢查。 |
| `from_fx_rate` | 必填 | 移出金額換算台幣匯率，依共通匯率規則。 |
| `to_amount` | 必填 | 移入帳戶金額，大於零；由資料庫 `CHECK` 限制。 |
| `to_currency` | 必填 | 三碼幣別，須符合移入帳戶幣別；由 API 在寫入前檢查。 |
| `to_fx_rate` | 必填 | 移入金額換算台幣匯率，依共通匯率規則。 |
| `transferred_at` | 必填 | 移轉時間，`timestamptz`。 |
| `note` | 可空 | 補充說明。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`from_account_id`、`to_account_id` → `accounts.id`。不同幣別帳戶間移轉時，移出與移入金額及各自匯率分別保存；API 在寫入前檢查實際換匯金額與匯率。

## 8. `instruments`（投資標的）

記錄股票、基金等投資標的，供多筆投資交易參照。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `market` | 必填 | 限 `tw_stock`、`us_stock`、`fund`、`other`；由資料庫 `CHECK` 限制。 |
| `symbol` | 必填 | 市場代號；同一市場與代號不可重複，由資料庫唯一約束限制。 |
| `name` | 必填 | 標的名稱。 |
| `currency` | 必填 | 幣別。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**無。

## 9. `trades`（投資交易）

記錄投資標的在帳戶發生的交易或公司行動。依交易種類才成立的欄位組合規則由 API 驗證。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `instrument_id` | 必填 | 投資標的；父列仍被參照時拒絕刪除。 |
| `account_id` | 必填 | 交易帳戶；父列仍被參照時拒絕刪除。 |
| `trade_type` | 必填 | 限 `buy`、`sell`、`cash_dividend`、`stock_dividend`、`drip`、`split`、`merge`、`capital_reduction`；由資料庫 `CHECK` 限制。 |
| `traded_on` | 必填 | 交易或公司行動日期。 |
| `quantity`、`price`、`cash_amount`、`ratio` | 可空 | 依交易種類使用；欄位組合規則由 API 驗證。 |
| `fee`、`tax` | 可空 | 有值時須大於或等於零；由資料庫 `CHECK` 限制。 |
| `currency` | 必填 | 交易幣別。 |
| `fx_rate_to_twd` | 必填 | 大於零；由資料庫 `CHECK` 限制。 |
| `voided_at` | 可空 | 作廢時間，`timestamptz`。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`instrument_id` → `instruments.id`；`account_id` → `accounts.id`。

## 10. `invoices`（統一發票）

記錄台灣統一發票基本資料，供留底、關聯花費及對獎。獨立成表，因發票可有多個品項、可關聯多筆花費，且中獎收入需以發票為來源。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `invoice_number` | 必填 | 兩碼大寫英文字母加八碼數字；由資料庫格式 `CHECK` 限制。 |
| `issued_at` | 必填 | 開立時間，`timestamptz`。 |
| `invoice_period_start` | 必填 | 發票期別起始日，`date`；須為奇數月份的第一日，由資料庫 `CHECK` 限制。 |
| `total_amount` | 必填 | 發票總額，不得為負。 |
| `currency` | 必填 | 三碼幣別。 |
| `fx_rate` | 必填 | 換算台幣匯率，依共通匯率規則。 |
| `seller_name` | 可空 | 店家名稱。 |
| `note` | 可空 | 補充說明。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**唯一性與外鍵：**`invoice_period_start` 與 `invoice_number` 的組合不得重複。無外鍵。

**期別規則：**使用 `issued_at` 換算成 `Asia/Taipei` 的當地日期，以該日期所在月份所屬的雙月期計算期別；例如一、二月期的起始日為當年一月一日，三、四月期的起始日為當年三月一日，依此類推。API 在寫入前檢查 `invoice_period_start` 是否符合開立日；資料庫另檢查期別起始日是奇數月份第一日。

## 11. `invoice_items`（發票品項）

記錄發票上的各個品項。獨立成表，讓一張發票可有多筆品項，不必把品項塞進發票欄位。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `invoice_id` | 必填 | 所屬發票；刪除發票時可連帶刪除此表品項，是唯一的級聯刪除例外。 |
| `item_name` | 必填 | 品項名稱。 |
| `quantity` | 必填 | 大於零的數量；由資料庫 `CHECK` 限制。 |
| `unit_price` | 必填 | 不得為負的單價；由資料庫 `CHECK` 限制。 |
| `line_amount` | 必填 | 不得為負的品項金額；由資料庫 `CHECK` 限制。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`invoice_id` → `invoices.id`，刪除規則為 `ON DELETE CASCADE`。幣別及匯率沿用所屬發票；API 在寫入前檢查品項金額與數量、單價的計算及捨入結果。

## 12. `invoice_expenses`（發票與花費關聯）

記錄發票與花費的對應關係。獨立成表以支援一張發票對多筆花費，也避免限制一筆花費只能由一張發票說明。此關聯不記分攤金額，因此花費合計不必等於發票總額。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `invoice_id` | 必填 | 發票。 |
| `expense_entry_id` | 必填 | 花費。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**外鍵：**`invoice_id` → `invoices.id`；`expense_entry_id` → `expense_entries.id`。

**唯一性：**`invoice_id` 與 `expense_entry_id` 的組合不得重複。

## 13. `invoice_prize_rules`（發票獎項與獎金）

保存各期開獎號碼、獎項及獎金金額，讓對獎資料與獎金金額存於資料庫，而非寫死在程式裡。獨立成表，因每期可有多個獎項及多組中獎號碼。

| 欄位 | 必填／可空 | 規則 |
|---|---|---|
| `id` | 必填 | 資料庫產生且不可變的整數主鍵。 |
| `invoice_period_start` | 必填 | 獎項所屬期別起始日，須為奇數月份第一日；由資料庫 `CHECK` 限制。 |
| `prize_type` | 必填 | 獎項名稱，例如特別獎、特獎、頭獎或增開六獎。 |
| `winning_suffix` | 必填 | 該獎項比對的數字尾碼，長度一至八碼且只含數字；由資料庫 `CHECK` 限制。 |
| `match_digits` | 必填 | 比對位數，介於一至八；須等於 `winning_suffix` 長度，由資料庫 `CHECK` 限制。 |
| `award_amount` | 必填 | 該獎項獎金，台幣金額且不得為負；由資料庫 `CHECK` 限制。 |
| `created_at`、`updated_at` | 必填 | 遵循共通時間規則。 |

**唯一性與外鍵：**`invoice_period_start`、`prize_type`、`winning_suffix` 的組合不得重複。無外鍵；期別及開獎資料由使用者維護。對獎時由 API 依發票期別、號碼尾碼及獎項資料判斷是否中獎。中獎獎金以 `income_entries.invoice_id` 連結為一筆入帳。

## 帳戶餘額與投資持有量的計算

- 現金、銀行及券商交割戶的餘額，以期初金額為起點，加上該帳戶入帳及移轉入帳，減去花費、移轉出帳、投資買進及股息再投入金額，再加上投資賣出金額。移轉兩端分別按各自帳戶幣別及金額計算。信用卡餘額用相同的正負方向計算；負值代表欠款，信用卡花費會增加欠款，付款移轉至信用卡會減少欠款。
- 投資標的持有股數為該標的所有投資交易 `shares_change` 的合計。成本與平均成本按投資交易計算；不在標的主檔存可修改的股數或平均成本。
- 所有餘額依帳戶原幣別計算。外幣換算台幣的報表金額，使用各筆資料保存的 `fx_rate` 換算。

## 這一次不建的表

- 預算表。
- 固定收支／週期性交易表。
- 載具自動匯入或載具資料表。
- 即時股價或行情表。
- 銀行同步、銀行連線或同步紀錄表。
- 複式記帳用的會計科目、分錄及借貸明細表。
- 用來刪除帳務列的功能或資料表。
